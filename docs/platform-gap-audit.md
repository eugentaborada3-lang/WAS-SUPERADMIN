# Super Admin specification and control audit

Source: `Water_Assistant_System_Complete_UIUX_Design_Specification.docx`, SA-01–SA-12. “Live” means the control uses persisted application data; it does not imply a real provider, delivery, or settlement connection. MySQL integration status is listed separately.

| Section | Required workflow | Current status |
| --- | --- | --- |
| SA-01 | Separate platform sign-in, MFA, recovery, lockout, sessions and access audit | Substantially live: separate platform identities/sessions/routes, mandatory TOTP enrollment and verification, one-use recovery codes, password recovery, failed-attempt lockout, session revocation, and authentication audit. SMTP delivery still depends on configured credentials; remembered-device and IP allow-list controls are not implemented. |
| SA-02 | Cross-utility dashboard, financial/operational KPIs, exceptions and health | Partial live: tenant, user, setup, incident, support, bill and recorded-payment counts come from persisted tables. ## Validation boundary

Go unit, vet/build and Svelte check/build can run locally. Destructive MySQL integration tests require an isolated database supplied through `WAS_TEST_DSN`; the normal development database must never be used. Svelte MCP documentation and autofixer tools were not exposed in this environment.
